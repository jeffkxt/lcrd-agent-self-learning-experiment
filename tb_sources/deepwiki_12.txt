This page defines the core terminology and fundamental concepts used throughout Terminal-Bench. Understanding these concepts is essential for working with the benchmark, whether you're running evaluations, creating tasks, or developing custom agents.

For detailed architecture information about how these components interact, see 
System Architecture
. For practical guidance on running benchmarks, see 
Running Your First Benchmark
.

Tasks

A 
task
 is the fundamental unit of evaluation in Terminal-Bench. Each task represents a self-contained challenge that an agent must solve in an isolated environment.

Task Structure

Every task consists of five required components:

Component

File

Purpose

Configuration

task.yaml

Task instruction, metadata, timeouts, parser configuration

Environment

docker-compose.yaml

Container definitions and dependencies

Oracle Solution

solution.sh
 or 
solution.yaml

Reference implementation for the task

Tests

tests/
 directory

Unit tests to validate task completion

Test Runner

run-tests.sh

Script that executes tests and outputs results

The 
Task
 class (

 - High-level classification (e.g., "software_engineering")

Configuration:

parser_name
 - Which parser to use (
ParserName
 enum)

max_agent_timeout_sec
 - Time limit for agent execution (default: 360s)

max_test_timeout_sec
 - Time limit for test execution (default: 60s)

run_tests_in_same_shell
 - Whether tests share shell state with agent

disable_asciinema
 - Disable terminal recording while keeping Docker

estimated_duration_sec
 - Expected completion time for metrics

Behavior

Use Case

Returns after

Long-running operations, ensures completion

Blocking mode works by appending

Failure Mode Determination

The harness determines failure mode through exception handling and test result analysis:

Agent Execution
 - Catches timeout, context length, and agent errors

Test Execution
 - Catches timeout errors

Result Analysis
 - Examines parser results for test failures

Default
 - 
FailureMode.NONE
 if all tests pass

Run Metadata and Reproducibility

Terminal-Bench ensures reproducibility through the 
RunLock
 system.

Resuming Runs

The harness can resume incomplete runs:

Reads 
tb.lock
 to validate configuration matches

Checks each task for complete trial results

Cleans up incomplete trial artifacts

Re-runs only incomplete tasks

This enables long-running evaluations to recover from interruptions without re-executing completed work.
